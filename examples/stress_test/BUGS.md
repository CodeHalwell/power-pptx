# Bugs surfaced by the stress-test suite

Generated by running every deck in `examples/stress_test/` through the harness
(`python examples/stress_test/_harness.py`), which checks each deck against
**build → lint → round-trip → reopen → ISO-29500 schema validation**.

Headline result: **round-trip is clean across all 13 decks and every deck
reopens** — but the ISO-29500 schema validator (the same one behind the
`schema-validation` CI job) caught **four distinct bug classes** that pass the
"does it reopen in python-pptx / LibreOffice" check yet would make Microsoft
PowerPoint report the file as broken / repair it.

All four are reproducible with a handful of lines and have a clear root cause.

> **Status: all four FIXED on this branch.** Each fix ships with a reproducing
> deck builder added to `tests/schema/test_schema_validity.py` so the
> `schema-validation` CI job guards against regressions. The full unit suite
> (3637 tests) and the behave acceptance suite stay green.

---

## Bug 1 — `slide.transition.duration` writes a bare `p14:dur` attribute (HIGH impact) — ✅ FIXED

**Surfaced by:** `07_transitions_torture` (25 slides), `13_mega_kitchen_sink` (14 slides)

Setting a transition duration emits the 2010-extension attribute `p14:dur`
directly on a plain `<p:transition>` element:

```xml
<p:transition xmlns:ns0="…/powerpoint/2010/main" ns0:dur="800">
  <p:fade/>
</p:transition>
```

`p14:dur` is only schema-valid inside an `mc:AlternateContent` /
`mc:Choice Requires="p14"` wrapper (the same wrapping the library *already*
does for p14 *kinds* like Morph). Because the bare attribute is invalid,
**every transition that sets a duration** is rejected. This hits classic kinds
(FADE, PUSH, …) too — not just p14 kinds.

```python
from power_pptx import Presentation
from power_pptx.enum.presentation import MSO_TRANSITION_TYPE
prs = Presentation(); s = prs.slides.add_slide(prs.slide_layouts[6])
s.transition.kind = MSO_TRANSITION_TYPE.FADE
s.transition.duration = 800          # <-- produces invalid p14:dur
# schema error: attribute '{…/2010/main}dur' is not allowed
```

**Root cause:** `src/power_pptx/oxml/slide.py` — the duration setter writes the
`p14:dur` attribute without promoting the transition into the AlternateContent
wrapper used for p14 kinds (see the wrapping helpers around lines 393–440).

## Bug 2 — Radar chart series emit a disallowed `<c:smooth>` element — ✅ FIXED

**Surfaced by:** `02_charts_torture` (chart8 = RADAR)

`XL_CHART_TYPE.RADAR` and `RADAR_MARKERS` write a `<c:smooth>` child into the
series. `CT_RadarSer` does not allow `smooth` (only `…/val` then `extLst`), so
the part is invalid. `LINE` charts are clean.

```python
from power_pptx import Presentation
from power_pptx.chart.data import CategoryChartData
from power_pptx.enum.chart import XL_CHART_TYPE
prs = Presentation(); s = prs.slides.add_slide(prs.slide_layouts[6])
d = CategoryChartData(); d.categories = ["A","B","C"]; d.add_series("S",(1,2,3))
s.shapes.add_chart(XL_CHART_TYPE.RADAR, 0, 0, 5000000, 4000000, d)
# schema error: Element 'c:smooth': This element is not expected. Expected is (c:extLst)
```

**Root cause:** `src/power_pptx/oxml/chart/series.py:150`
(`smooth = ZeroOrOne("c:smooth", …)`) is on the shared series class, and the
radar plot builder emits it. `smooth` should be suppressed for radar series.

## Bug 3 — `PresetMaterial.SOFT_METAL` emits `softMetal`, but the schema enum is `softmetal` — ✅ FIXED

**Surfaced by:** `05_three_d_torture` (slide 2)

The ISO-29500 `ST_PresetMaterialType` enumeration spells this value
all-lowercase (`softmetal`) — a quirk of the spec — but the library emits the
camelCase `softMetal`, which fails enum validation.

```python
three_d.preset_material = PresetMaterial.SOFT_METAL   # writes prstMaterial="softMetal"
# schema error: value 'softMetal' is not an element of the set {…, 'softmetal'}
```

**Root cause:** `src/power_pptx/enum/dml.py:645`
`SOFT_METAL = (14, "softMetal", …)` — the XML value should be `"softmetal"`.

## Bug 4 — Picture recolor `"washout"` drops the required `thresh` attribute — ✅ FIXED

**Surfaced by:** `10_picture_svg_torture` (slide 2)

`pic.effects.recolor = "washout"` writes an `<a:biLevel>` element with **no
`thresh` attribute**, which the schema requires.

```python
pic.effects.recolor = "washout"
# schema error: Element 'a:biLevel': The attribute 'thresh' is required but missing.
```

**Root cause:** `src/power_pptx/dml/picture.py:144` sets
`get_or_add_biLevel().thresh = 0.5`, but `thresh` is declared as
`OptionalAttribute("thresh", ST_PositiveFixedPercentage, default=0.5)` in
`src/power_pptx/oxml/dml/fill.py:262`. Because the assigned value (`0.5`) equals
the declared default, the serializer omits the attribute — and `thresh` is a
**required** attribute on `CT_BiLevelEffect`. Declaring it as a
`RequiredAttribute` (or writing it unconditionally) fixes it.

## Things that held up well

- **Round-trip (the release gate):** clean for all 13 decks, including charts,
  3D, p14 morph/vortex/conveyor transitions, duotone pictures, SVG embedding,
  diagrams, tables with merged cells, and `import_slide` / `apply_template`.
- **Reopen:** every saved deck re-opens in power-pptx.
- **Linter:** correctly flagged every planted overflow (now auto-fixed to
  `TEXT_TO_FIT_SHAPE`) and every off-slide shape (clamped back on-slide).
- **`apply_palette` on pie/doughnut:** emits a helpful warning and auto-routes
  to `color_by_category()` rather than failing.

## Minor doc nit

- `references/tables.md` states an unset `cell.borders.<edge>.width` reads back
  as `None`; it actually returns `Emu(0)` — but that is upstream-consistent
  (a plain shape's `line.width` does the same). Doc wording, not a code bug.
